
# CONFI UI Design Rules

## Design philosophy
Design CONFI as a carefully crafted desktop utility, not a generic SaaS dashboard.
It should feel like a mature, reliable file-management application.

## Visual direction
- Functional, minimal, precise, and professional.
- Strong typography and clear visual hierarchy.
- Neutral surfaces with a restrained accent color.
- Consistent spacing, alignment, and component sizing.
- Dense enough to be useful, never cluttered.
- Prioritize the files and the operations being performed.

## Avoid
- Purple/blue gradient backgrounds.
- Glassmorphism and glowing borders.
- Oversized rounded cards and floating panels.
- Excessive empty space.
- Decorative icons that add no meaning.
- Fake statistics, charts, and dashboard widgets.
- Generic SaaS landing-page layouts.
- Unnecessary animations and hover effects.

## Product-specific requirements
- PDF operations should be immediately discoverable.
- File lists, thumbnails, drag-and-drop, and batch queues are first-class UI elements.
- Show clear input files, output format, destination, progress, and errors.
- Make destructive actions explicit and preserve originals by default.
- Use native platform conventions where appropriate.
- Windows and Android should feel like the same product, not identical layouts.

## Design workflow
1. Study real desktop file utilities before designing.
2. Establish typography, colors, spacing, and component rules first.
3. Design the main application window before secondary screens.
4. Reuse components consistently.
5. Run the application and inspect actual screenshots.
6. Refine visual problems before adding more features.

Do not call a design finished just because it compiles.
